Mesh-to-CFD Validation

Mesh-to-CFD Validation is a dedicated mode in the OneFLOW Tests dialog. It is separate from Run Development Cases, which continues to execute individual preconfigured Cases.

The initial conversion route is:

selected STL-to-Gmsh Case -> Gmsh MSH -> Gmsh-to-CGNS Case
    -> CGNS-to-OneFLOW Case -> selected CFD template

The mesh producer can be either the native C++ OneFLOW Grid task or an independent Python reference Case. Both implementations publish the same Case-specific MSH artifact contract. Native Cases declare the artifact path in script/grid.txt; Python Cases declare the mesh filename in expected.json. The language-specific producer is selected from the Case Catalog, while the downstream conversion and validation graph is shared.

The first CFD consumer is the existing test/cfd/plateuns2dslau2 Laminar Flat Plate Case. Each source Case is copied into a unique directory under ~/.oneflow/mesh-validation (or the equivalent user-home directory on Windows). Runtime parameter changes are applied only to those copies. Every producer and consumer process runs with its own staged Case directory as its working directory. Users do not edit workflow JSON or manually copy intermediate files.

The default solver smoke test advances two steps. A square mesh with the flat-plate template tests conversion, native-grid ingestion, initialization, and short time advancement; it is not a physical flat-plate validation. Each stage writes a log, and the run writes mesh-validation-report.json. Additional CFD templates, including a turbulent flat plate, can be registered as this mode evolves.

Boundary type mapping

The Gmsh-to-CGNS adapter maps common Physical Group name aliases to CGNS BCType_t values. Matching is case-insensitive and ignores punctuation; the original Physical Group name is retained as the boundary patch name.

Inlet, Inflow, VelocityInlet, MassFlowInlet, PressureInlet

Wall, LowerWall, UpperWall, BodyWall

SlipWall, InviscidWall

BC::SOLID_SURFACE

Symmetry, SymmetryPlane

Farfield, Freestream

BCFarfield

BC::FARFIELD

unrecognized names

BCTypeUserDefined

BC::GENERIC_2 (existing fallback)

This mapping is deliberately a boundary-type mapping, not a complete physical boundary-state definition. BCInflow does not specify velocity, mass flow, temperature or turbulence quantities. BCOutflow does not specify a target pressure. Mapping NoSlipWall to the broad OneFLOW SOLID_SURFACE category does not prove that a particular viscous wall treatment is configured. The original name and CGNS type are retained for diagnostics and later richer contracts.

Periodic connectivity is not inferred from a name such as Periodic: CGNS periodic interfaces are represented through zone connectivity metadata, not as a BCType_t member in the enum. Neumann, Dirichlet, degenerate and other CGNS types remain unmapped until their OneFLOW semantics and numerical treatment are explicitly defined.

The Mesh-to-CFD dialog displays this common mapping as a quick reference. It is not a compatibility approval: physical problem type, required boundary state data and solver support must still be checked before a CFD template runs.
