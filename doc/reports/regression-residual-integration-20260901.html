本阶段将普通回归和高精度回归统一到同一个测试 runner、同一个五案例 suite 和同一个结构化 residual baseline。普通模式继续服务 GitHub CI；严格模式使用同一套入口，将绝对容差收紧到 1e-15，并启用 max-digits10 残差文本输出。

3. 标准 residual 的形成与校验

  1. 从 suite 文件收集各案例的 autotest/res.dat 和 autotest/turbres.dat。
  2. 由 build_residual_db.py 生成带 schema、suite、launcher、容差策略、行列摘要和 SHA-256 的 JSON 数据库。
  3. 由 verify_residual_db.py 校验 baseline 自洽性、文件存在性、列名、行数、摘要和哈希。
  4. 运行时由 residual_db.py 做逐值比较；严格模式额外要求迭代列和行数完全一致。

本地校验结果：residual database OK: 5 cases, 8 files；git diff --check 通过。旧的 residual-baseline-e15.json 和 *.full.dat 双体系已移除，避免标准与实际测试路径分叉。

普通快速回归（GitHub CI / 本地）：

  suites/cpu-serial.txt baselines/residual-baseline.json 1e-8

严格回归（昆山 CPU 队列优先）：
ONEFLOW_RESIDUAL_TEST_OUTPUT=1 python3 test/test.py "mpirun -np 1" "/path/to/OneFLOW" \
  suites/cpu-serial.txt baselines/residual-baseline.json 1e-15
