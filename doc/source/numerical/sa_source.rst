Spalart-Allmaras source residual
================================

The SA working-variable transport equation combines production, destruction,
and a limited cross-diffusion contribution. The pure policy functions below
represent the scalar algebra used by the production implementation.

Model terms
-----------

.. math::

   P = c_{b1}(1-f_{t2})\\tilde\\nu_{S}\\tilde{S}

.. math::

   D = (c_{w1} f_w - c_{b1} f_{t2})\\tilde{\\nu} r_s

.. math::

   D_{\\mathrm{diff}}
   = \\min\\left(r_p P,\\,
   \\frac{c_{b2}}{\\sigma}
   |\\nabla\\tilde{\\nu}|^2/Re\\right)

.. math::

   S_{\\tilde{\\nu}} = P - D + D_{\\mathrm{diff}}

The spectral contribution uses the negative part of a scalar rate:

.. math::

   x^- = -\\frac{1}{2}(x-|x|)

The implementation uses precombined inputs at this policy boundary:
cw1k represents the coefficient multiplying fw in the destruction term;
nuTildeRs represents the product of the working variable and rs; and
cb2OverSigma represents cb2 divided by sigma. The caller computes these
values from the active model constants and local flow state.

Formula-level verification
--------------------------

tests/solver/turb_sa_policy_test.cpp checks each source component against
fixed values independently evaluated from the equations above. The test set
also checks both branches of the diffusion limiter, the final signed
combination, and the piecewise negative-part function.

These tests establish the scalar algebra at the pure-policy boundary. They
do not prove that the caller supplies the correct gradients, wall distance,
strain measure, Reynolds scaling, model variant, or boundary values. Those
require separate component and flow-level evidence.

Verification and validation are different questions
----------------------------------------------------

The NASA Turbulence Modeling Resource (TMR) explicitly separates code/model
verification from validation:

* The SA model definition at
  https://tmbwg.github.io/turbmodels/spalart.html documents the standard SA
  equations, constants, and model variants. Standard SA must not be confused
  with SA-neg, SA-noft2, or correction variants.
* The 2D zero-pressure-gradient flat-plate verification case at
  https://tmbwg.github.io/turbmodels/flatplate.html provides nested grids
  and reference solutions intended to check whether an implementation
  follows the specified equations and boundary conditions.
* The corresponding flat-plate validation case at
  https://tmbwg.github.io/turbmodels/flatplate_val.html compares quantities
  of interest such as skin-friction coefficient versus momentum-thickness
  Reynolds number and mean velocity profile u+(y+) against theoretical
  correlations.
* Eca, Hoekstra, Hay, and Pelletier (2005) provide a manufactured solution
  that includes source functions for the Spalart-Allmaras transport
  equation. This is a stronger route for checking the assembled differential
  operator and its source terms than comparing only a converged engineering
  flow.

A source term is not generally a directly measured experimental observable.
Therefore, compare its scalar components with the governing equations,
published model definitions, and manufactured-solution expressions.
Compare observable flow quantities (for example Cf, u+(y+), and Re_theta)
with TMR reference correlations or experimental/DNS data in a separate
validation study.

A plotted curve is useful only when its provenance is explicit: record the
equation or dataset, model variant, constants, nondimensionalization,
sampling points, and the code path that generated the OneFLOW values.
Do not treat a plot generated by a second copy of the same implementation
formula as independent verification.
