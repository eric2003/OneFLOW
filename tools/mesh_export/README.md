# Minimal Rectangle Mesh Export Case

This case turns a mesh generated by OneFLOW into inspectable data files and two visualization outputs. It is deliberately small enough to validate by eye and by hand.

## 1. Generate the source mesh

Use the existing layout fixture:

- Layout: `tests/geometry/data/minimalRectangleLayout.txt`
- Generator: `GridMachine`
- Existing regression case: `GridLayoutGenerationTest.GeneratesMinimalRectangle`

The current fixture describes a unit square with 3 nodes along each direction. The generated structured grid therefore has 9 nodes and 4 quadrilateral cells.

The C++ case normally removes its temporary output. To preserve the actual OneFLOW-generated file for inspection, set the opt-in environment variable and run the existing test executable:

```powershell
$env:ONEFLOW_KEEP_MESH_EXPORT_CASE = "1"
.\\path\\to\\GridLayoutGenerationTest.exe --gtest_filter=GridLayoutGenerationTest.GeneratesMinimalRectangle
```

The test prints the retained `.ofl` path, normally under the system temporary directory in `oneflow-minimal-rectangle/minimalRectangle.ofl`. Then pass that exact path to the exporter below. Without the environment variable, the test retains its original cleanup behavior. The exporter expects the structured binary header checked by this case: zone count, `ni`, `nj`, `nk`, then the x, y, and z coordinate arrays.

## 2. Export metadata and views

Run from the repository root:

```sh
python tools/mesh_export/export_structured_grid.py path/to/minimalRectangle.ofl
```

If the build writes 32-bit coordinates, pass `--real-bytes 4`. The default is 64-bit coordinates and little-endian data. The first version intentionally rejects multiple zones and non-2D structured grids instead of silently misreading them.

The output package contains:

- `summary.json`: L0 counts and reconstruction capability
- `geometry.json`: ordered coordinates
- `topology.json`: quad connectivity and face owner/neighbour data
- `boundary.json`: boundary-face membership
- `manifest.json`: schema versions and capability flags
- `views/mesh.svg`: lightweight grid drawing viewable in a browser
- `views/mesh.vtu`: VTK XML unstructured grid for ParaView and VTK/PyVista

The first case reconstructs 2D cell and edge topology from structured dimensions. The source header does not contain physical boundary names, so the exported boundary region is generic and explicitly marked as such. It does not claim to preserve OneFLOW boundary-condition semantics or partition/interface maps.

## 3. Hand-check the result

For the unit-square fixture:

- nodes: 9
- cells: 4
- unique edges/faces: 12
- boundary edges: 8
- internal edges: 4

These counts are useful sanity checks, but the coordinate and connectivity arrays are the actual reconstruction data. Open `views/mesh.svg` in a browser, or open `views/mesh.vtu` in ParaView.

## 4. Scope of this first case

This is the first end-to-end bridge from an existing OneFLOW-generated grid file to portable information files and visualization. It is not yet a general exporter for arbitrary unstructured meshes. The next increment should attach the same package-writing boundary to a live `UnsGrid` snapshot, so face boundary types and interface metadata come from the mesh rather than being inferred from structured dimensions.
